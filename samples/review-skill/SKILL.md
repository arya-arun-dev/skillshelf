# Review a small code change

## Purpose
Help a developer review a change for correctness and maintainability.

## Instructions
1. Ask what behavior the change is intended to produce.
2. Read the changed code and its relevant callers before making claims.
3. Check input handling, boundary cases, error paths, and resource cleanup.
4. Identify tests that would detect meaningful regressions.
5. Report concrete findings with file locations and explain their impact.
6. Separate confirmed issues from questions. If no issues are found, say so.

Do not execute commands or modify files unless the developer authorizes it.
